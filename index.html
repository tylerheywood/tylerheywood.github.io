VendAhead

Production SaaS platform for street food vendors. Capacity-aware pre-ordering that transforms reactive service into planned production.

Problem

Street food vendors deal with chaotic demand, long queues, unpredictable prep cycles, and lost sales. Customers walk away. Vendors cannot plan. Revenue leaks at both ends.

Approach

Built a web platform that allows customers to pre-order into time slots, giving vendors predictable demand and operational control. Multi-tenant architecture with vendor-specific storefronts and Stripe Connect for payment processing.

Outcome

Transforms reactive service into planned production. Reduces queue pressure, improves throughput, and gives vendors data they have never had access to before.

Key Capabilities

Capacity-controlled ordering. Time-slot scheduling. Vendor-specific storefronts. Stripe Connect payment processing. Multi-tenant architecture. Live deployable system.

AP Inbox Control System

Problem

AP teams manually sort through inboxes, cross-reference PO numbers, flag duplicates by eye, and track exceptions in spreadsheets. Slow, error-prone, and unauditable.

Approach

Built a Python system that ingests invoice emails, extracts financial data from PDFs, validates against PO references, and surfaces exceptions through a purpose-built dashboard.

Outcome

Eliminated manual inbox sorting. PO validation and duplicate detection run automatically. Full audit trail for every decision. Deployed on Linux with Nginx and HTTPS.

Key Capabilities

Email ingestion. PDF data extraction. Deterministic PO matching. Duplicate detection. Exception dashboard. Traceable audit trail.

How I Create Leverage

Automation

I identify repetitive operational work and replace it with deterministic systems. Email processing, invoice validation, data extraction. If a human is doing it manually and repeatedly, I build the thing that does it automatically.

Risk & Controls

I surface financial risk that is currently invisible. Duplicate invoices, missing PO references, processing exceptions. I build systems that catch these consistently, not when someone happens to notice.

Data Systems

I take scattered data in spreadsheets, inboxes, and disconnected tools and consolidate it into structured, queryable systems. Clean data in, reliable decisions out.

Process Redesign

I map existing workflows, find where effort is wasted or risk is hidden, and redesign the process before automating it. The system should reflect how work should flow, not how it accidentally evolved.

Rapid Prototyping

I move from problem to working system quickly. Python, SQL, web interfaces. I choose the shortest path to a deployable solution and iterate from real usage, not specifications.

Product Thinking

I build tools that people actually use. Vendor storefronts, control dashboards, risk reports. Designed for the end user, not the developer. If adoption fails, the system is worthless.
